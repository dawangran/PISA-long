# PISA 长读 GX 注释规则提案

状态：本稿已实现为独立的 `-gene-only-v2` 实验模式，原 `-gene-only` 保留为 v1 基线。参数仍需校准，实验实现不表示规则已获生物学验证。所有示例均用于说明规则；本仓库不包含研究样本数据。

2026-11-05 审查结论：此稿保留为候选方案，**不应直接将当前实验模式视为正式默认方案**。下文第11节记录已验证的两个逻辑反例及一个GX使用边界；实验模式保留这些边界行为用于比较，尚未修订为新的定稿。

目标：GX 用作后续按基因分组的键。只要存在基因候选就保留 GX；减少小段纯内含子命中造成的单基因/多基因标签跳变，保留真正无法区分的候选。没有任何基因重叠时不能编造 gene_id。

## 1. 注释单位和边界

- 当前 PISA C 注释单位是 alignment，每条 primary、secondary、supplementary 各自计算。
- 本提案首先定义这一层的规则，不把同名多条 alignment 当作多个独立分子，也不声称单条 primary 就包含全部 read 证据。
- 同一 read 最终获得统一 GX 仍需在完整比对集合上汇总：primary+supplementary 用原始 query 坐标并集；secondary 作为替代解释，不能累加为主链支持。缺失片段和冲突应保留状态，不清除已有候选证据。
- 本次不改变比对、不剪切 read、不删除记录，不使用 CB/UR 反过来强行统一基因归属。
- 可以使用 `-ignore-strand` 忽略链方向；应根据文库信息选择，不把 FLAG 正反链直接当作已确认的转录方向。

## 2. 一次性建立 GTF 索引

对每个 gene_id 保存 gene body、所有转录本外显子的区间并集、已知内含子坐标集合。外显子取并集，避免多个转录本重复累计相同碱基。

已知 junction 只作额外证据和防止误删候选的条件；不要求 read 匹配已知转录本，也不因新 junction 拒绝注释。严格匹配已知 junction 的两端坐标，并要求两侧存在实际比对支持；未匹配不等于错误。

## 3. 原始证据

只计 CIGAR `M/=/X`；M 包含可能的 mismatch，不代表逐碱基验证为正确匹配。N、D、I、S、H 不提供 gene body 覆盖。

设 Q 是实际比对碱基位置集合，L=|Q|。对所有有正重叠的基因 g 计算：

| 量 | 定义 |
|---|---|
| S_g、B_g | 落入 gene body 的比对位置集合及长度 |
| T_g、E_g | 落入该基因外显子并集的位置集合及长度 |
| U_g | S_g 扣除全部其他候选 S_h 的并集后的长度 |
| X_g | T_g 扣除全部其他候选 T_h 的并集后的长度 |
| J_g | 该 alignment 支持的该基因已知 junction 集合 |
| C_all | 全部候选 S_g 并集长度除以 L |

所有量在原始候选集合上计算一次，不能删除候选后再更新分母或重新寻找赢家。

候选出现没有 100 bp 门槛：只要 B_g>0 就保留到原始证据。L 是实际比对碱基长度，不是基因组跨度、gene body 长度或包含 soft clip 的整条 read 长度；完整 read 比对比例另作记录。

## 4. 先确定是否有可用的主候选 A

只有一个原始候选时直接保留它的 gene_id，不需要通过弱候选消减。

存在多个候选时，以以下可配置工程预设找主候选：

```text
U_g/L >= 0.20
并且满足以下至少一项：
    B_g/L >= 0.80
    X_g/L >= 0.50
```

- 第一条要求相对充足的独占 gene-body 支持，防止单靠共享区域选赢家。
- 第二条的 80% 路径允许不依赖已知外显子的主体覆盖证据。
- 50% 路径用于外显子特异支持已覆盖多数实际比对碱基、但还有未被注释解释片段的情况；输出需标为 partial，不能当作全长已解释。
- 恰好一个基因满足时才使用它作 A。没有或多个满足时，不按字典序、最长 gene body 或单纯最大 B_g 强选；保留全部候选。
- MAPQ 不可用/低质量/QC-fail 等情况下，不执行自动候选消减；仍写候选 GX 和质量状态。质量门槛沿用 PISA 的 `-q`（当前默认0），不把 MAPQ255 当作高置信。

这些比例用于决定何时允许简化 GX，不是后验概率。50%、80%、20% 均需要分读长和区域校准。

## 5. 共享候选 H

在原始证据上，其他候选 b 只有同时满足以下条件，才可视为 A 已解释的共享候选：

```text
S_b 完全包含在 S_A 中
T_b 完全包含在 T_A 中
J_b 是 J_A 的子集
```

也就是 b 没有 A 之外的 body 支持、外显子支持或已知 junction 支持。由于 A 还必须通过第4步独占支持条件，read 只落在共享区域时不会触发此简化。

不再使用“b 超过100 bp就否决A”的规则。嵌套基因如果有 A 不能解释的外显子/junction 证据，保留它；不能仅因 body 被包含就移除。

## 6. 纯内含子的弱候选 W

存在明确 A 时，对尚未属于 H 的其他候选，只有全部满足下面条件才进入弱候选集合 W：

```text
E_b == 0
J_b 为空
B_b/L <= 0.10
```

这里“纯内含子”准确指在该 gene body 内、但不落入其任何已注释外显子的支持；它仍可能包含未注释的新结构，所以只从最终分组候选中降级，不删除比对和原始证据。

随后必须计算所有 W 支持位置的并集：

```text
|union(S_b for b in W)| / L <= 0.10
```

合计满足时一次性移出全部 W；合计超限则 W 全部保留。不逐个删、不反复重排，因此不会因候选遍历顺序产生不同结果。仅仅每个候选小于10%还不够。

10% 是待校准的弱证据预设，可比较5%/10%/15%；不能为让一条 read 变成单基因而单独改值。相对主候选的20%条件无需另设：A 至少覆盖50%，W单项不超过10%，该比例已不超过20%。任何硬阈值仍会有边界跳变；这里减少固定长度带来的不合理变化，并不承诺所有同分子reads的GX必然一致。

## 7. GX、GN 和状态

原始候选始终完整保留。最终候选 K 仅在有明确 A 时，按上面规则一次性去除 H 和可忽略 W，否则 K=原始候选。

| 情况 | GX | 状态建议 |
|---|---|---|
| K只有一个基因，B/L>=80% | gene_id | ZA=unique |
| K只有一个基因，0<B/L<80% | gene_id，仍保留 | ZA=assigned_partial，ZR记录覆盖量及降级原因 |
| K有多个基因 | AMBIG:按gene_id排序并以`\|`连接 | ZA=ambiguous；覆盖不足或跨基因结构写入ZR |
| 没有任何正重叠基因 | 不制造统一假gene_id | ZA=unassigned |
| 比对质量有问题且存在候选 | 单候选gene_id或排序组合，仍保留 | ZA=low_mapq/unknown_mapq/qc_fail等，ZR保留其他说明 |

GN 保存相应的名称，不作稳定主键。GX 不携带百分比、bp数、CB或UR，避免这些变化造成新的分组键。

仍保留现有 ZG/ZN/ZB/ZQ 原始标签；新增外显子、独占量、候选降级理由可先输出审计TSV，若增加 BAM 自定义 tag，实施时需检查冲突并在README逐一登记。

在 PISA alignment 层，跨多个基因不直接输出“已确认融合”。可以在ZR标记跨基因支持供提取，但这里没有验证断点或融合事件。

## 8. 部分归属的数值示例

假设实际比对长度L=2000，基因A有1250 bp独占外显子支持，基因B有150 bp纯内含子支持且无已知junction，另外600 bp不在这两个gene body内。

- A的独占body和外显子支持均为62.5%，通过主候选的外显子路径；B不通过。
- B的纯内含子支持占7.5%，弱候选合计也占7.5%，可以降级。
- 输出 `GX=A`、`ZA=assigned_partial`，同时保留A/B原始候选及支持量。
- 这只是按规则得到的暂定标签，不证明B片段错误，也不证明整条read来自A的普通转录本。

## 9. 必须覆盖的验证情况

- 两基因支持从99变100或101 bp，不再仅因越过这个绝对值改变GX。
- A有5000bp、B有101bp且全部是A可解释的共享证据：不被100bp上限否决。
- read全部落在A/B共享区域：没有主候选，保留AMBIG。
- B有少量但独立的已知外显子或junction证据：不应用纯内含子弱候选规则。
- 多个纯内含子候选各占8%、合计并集24%：不忽略全部候选。
- L=10000但只有A200bp、B165bp：没有主候选，不因A较大就压低B。
- 单基因的新junction或内含子覆盖：仍可保留该基因GX。
- 任意候选输入排序均产生相同GX；共享支持不重复累计。
- 原始记录、序列、CB/UR及非注释字段保留。

## 10. 使用边界

UMI-tools按GX的整个字符串分组，不自动理解AMBIG集合，也不自动读取自定义ZA状态。单基因partial GX与同基因unique GX相同，因此直接按GX去重时它们可能被分到一起；这正是保留主基因键的行为，同时必须在输出说明中明确，不能把partial标记当成自动保护机制。

来源：UMI-tools官方dedup文档关于`--per-gene`、`--gene-tag`、`--assigned-status-tag`和`--skip-tags-regex`：
https://umi-tools.readthedocs.io/en/latest/reference/dedup.html#single-cell-rna-seq-options

现有Python汇总脚本仍包含旧100bp/80%规则，并会覆盖GX。因此不要将它接在v2后并期待保留v2的判定。若需要v2的read级流程，仍须另行实现并验证相应汇总规则；该工作尚未完成。

## 11. 2026-11-05 规则审查

以下反例说明规则本身的限制，合成回归测试也保留这些行为。测试验证的是实现是否符合当前规则，而不是生物学正确性。

### 反例一：1 bp外显子重叠造成GX跳变

构造L=1992，A支持1238bp且均为其特有外显子，B在不重叠的另一片段支持165bp。其余589bp无基因覆盖，双方无已知junction。

| B的外显子支持 | 按本稿规则得到的GX |
|---:|---|
| 0 bp | A |
| 1 bp | AMBIG:A\|B |

原因是`E_B==0`也是硬开关。仅将100bp门槛替换为比例，再要求外显子支持严格为零，仍不能解决微小边界变动造成的分组键变化。应按外显子证据量与相对支持判断其是否构成竞争，不能把任意1bp重叠都视为强证据；具体规则尚待校准。

### 反例二：嵌套基因无法进入主候选路径

构造L=1000，read全部位于HOST与NEST的body中，1000bp都是NEST特有外显子，HOST外显子支持为零，NEST另有两个特有已知junction。两基因的独占body支持均为零。

按本稿规则仍得到`GX=AMBIG:HOST|NEST`、没有主候选。原因是20%独占body要求被放在所有路径的共同前置条件中，阻止了具有强外显子/剪接证据的候选被进一步区分。body独占与外显子/剪接支持应作为可分别评估的证据路径；不能把body几何关系等同于所有证据都不独占。

### 使用边界：有GX不等于已确定来源

本稿对单候选无论覆盖多少都保留gene_id；覆盖极少的partial记录与高覆盖unique记录使用同一GX。直接按GX去重时，ZA不会自动区分它们。保留GX是该实验模式的行为，但不能宣称所有这样的GX都已被验证为可靠归属。

任何单条read的预期标签都不应直接作为准确性的阳性真值。后续验证应包含多个基因区域、嵌套/重叠基因、长短read和边界扰动；不能只以某条read得到期望标签作为成功标准。
